# Microcks Deep Ink

The Microcks UI v2 design system, a proposal for the maintainers. **The contract is the source of truth; the interface makes it alive.** Every API wears its badge, every mock shows its URL, every test shows its proof.

Deep Ink evolves the current "Contract Workbench" (PatternFly 3 + Bootstrap). It keeps that system's discipline: dense layouts, explicit labels, the protocol spectrum and semantic status. What changes is the material: a blue-black ink ground, the logo's blues, a brand typeface taken from the wordmark, and one signature component, the **API badge**.

## Principles

1. **Contract first.** Paths, URLs and payloads are shown in `mono` and can be copied in one click. Every screen answers: *which contract, which operation, which proof?*
2. **Density with air.** We keep the workbench density, but separate jobs with the `space-6` rhythm, not with nested cards.
3. **Light over shadow.** Each elevation step lightens the ink one notch (`bg` → `canvas` → `surface` → `raised`). Shadows exist only for overlays (`shadow-overlay`) and focus (`shadow-focus`).
4. **Color is data.** Protocol colors identify API types. Status colors report outcomes. `live` pink marks real-time activity. None of them is decoration.
5. **Both themes, same meaning.** Deep Ink (dark) is the default; Paper (light) is a full peer. Every token has a value in both themes, at 4.5:1.

## Content fundamentals

- **Voice:** technical, direct, credible. Write "3 examples, URI_PARTS dispatcher", not "Your amazing mock is ready!".
- **Names:** use Microcks terms exactly: *Service, Operation, Example (sample), Dispatcher, Test runner, Importer, Artifact (primary/secondary), Secret, Snapshot, Hub*.
- **Language:** the UI is written in English.
- **Numbers:** conformance as `92%`; counts before nouns ("3 operations").
- **AI content** is always labelled: "Generated by AI, review needed", with the `warning` color and a spark icon, until a human accepts it.
- **Never invent** adoption, performance or compatibility claims (see PRODUCT.md).

## Visual foundations

### Color

| Role | Tokens |
| --- | --- |
| Ink ground (dark) | `bg` #070B14 · `canvas` #0B1220 · `surface` #101A2C · `raised` #16233A · `border` #22324F |
| Action | `action` (Microcks Blue #2E9BF0 dark / #0B6BC4 light) with `on-action` text |
| Links & values | `link` (Cloud Blue #86CEF5 in dark) |
| Protocols | `proto-rest` · `proto-soap` · `proto-event` · `proto-grpc` · `proto-graphql` · `proto-direct` |
| Outcomes | `success` · `danger` · `warning` · `running`, always icon + word |
| Live | `live` (Baseline Pink, from the logo tagline), only for streaming or real-time signals |

**The pink rule.** `live` is the logo's baseline pink. It marks real-time activity only (a test streaming, live traces, an import in progress). It is never used as a status. Failures use `danger` coral, which differs from pink in lightness and always carries a ✕ icon.

### Typography

- **Alegreya Sans SC** (`brand`): the face of the Microcks wordmark and tagline. Use it for page titles, service names, and big numbers. Never for body text or data.
- **IBM Plex Sans** (`ui`): all interface text. Engineered, neutral, excellent in dense tables.
- **JetBrains Mono** (`mono`): paths, URLs, payloads, identifiers, badges.

Fonts load from Google Fonts:
`https://fonts.googleapis.com/css2?family=Alegreya+Sans+SC:wght@500;700;800&family=IBM+Plex+Sans:wght@400;500;600&family=JetBrains+Mono:wght@400;600&display=swap`

### Shape

The radius has a meaning: `radius-control` 4px for sturdy controls, `radius-badge` 6px for API badges, `radius-panel` 8px for panels, `radius-node` 12px for direct-manipulation targets (drop zones, trace nodes, the command palette). `radius-pill` is reserved for label chips and the live dot.

### Layout

Shell = top bar (logo, ⌘K command bar, *Import a contract*, theme toggle, user) + left nav (Cockpit, APIs & Services, Workflows, Tests, Sources, Usage & conformance, Live traces, Hub, Administration) + fluid content. Pages are fluid: split views stack under 768px, wide tables scroll inside their box.

## Signature: the API badge

A two-segment shield, a visual language familiar to developers. The **left segment** says *what*: a protocol (filled with its `proto-*` color, `on-proto` text) or a metric label (`raised`, `text-secondary`). The **right segment** says *who* or the *proof*: service name + version on `surface`, or a status fill (`success`, `danger`, `warning`, `link`).

The badge is a purely visual identity inside the UI: it replaces the current protocol rings and labels. It does not imply any new backend feature.

Standard badges: `REST | API Pastry 2.0` · `conformance | 92 %` · `last test | ✕ failed` · `mcp | agent-ready` · `samples | 3 + 2 AI`.

## Workflows (Arazzo), a v2 proposal

Arazzo (OpenAPI Initiative) chains API operations into workflows. Deep Ink gives workflows their own identity without stealing a protocol color:

- **Workflow badge:** an inverted left segment (`text` fill, `bg` text) labelled `ARAZZO`, followed by the workflow name and document version.
- **The Loom** (see WorkflowLoom): lanes per source and data threads between steps. Arazzo means "tapestry".
- **Double proof:** every step reports its workflow criteria and its contract conformance separately. A 200 that violates the OpenAPI schema is still a failure.
- **Run targets:** each source of a run can point to Mocks, Staging or a custom URL, so a provider can be tested while its neighbours stay mocked.

## Iconography

Inline stroke icons, 2px stroke, 16–18px, `currentColor`, `aria-hidden` when next to text. No emoji. Protocol identity is always carried by text in a badge, never by an icon alone.

## Interaction patterns

- **⌘K command bar** everywhere: jump to a service or operation, or run an action ("Run a test on API Pastry 2.0").
- **Drop a contract anywhere:** dropping a file on any screen opens the import preview.
- **Preview before commit:** imports show the detected services and operations before writing anything.
- **Ghost rows** for AI-generated examples: shown inline, dashed, with *Accept / Edit / Reject*.

## Accessibility

Text at 4.5:1 in both themes (`text-muted` included). Focus = `action` border + `shadow-focus`. Touch targets of at least 44px for primary actions. Status is never color-only.
