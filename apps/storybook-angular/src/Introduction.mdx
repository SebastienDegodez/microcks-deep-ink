# Microcks Deep Ink · Angular

The Microcks UI v2 design system, a proposal for the maintainers.
**The contract is the source of truth; the interface makes it alive.**

This Storybook shows the **Angular** version of the registry. Nothing is installed from npm: you copy the
files you need into your app, then you own them. The React Storybook renders the same CSS, so both look the same.

## How it is built

- **Native elements first.** Single elements are attribute directives on the native element (`button[mkButton]`,
  `input[mkInput]`, `table[mkTable]`, `dialog[mkDialog]`). Composite widgets are standalone components (`mk-tabs`, `mk-field`, `mk-app-shell`).
- **Signals.** Inputs use `input()`, two-way state uses `model()`, events use `output()`. Components are standalone and `OnPush`.
- **Accessibility is a contract.** RGAA 4.1.2 (about WCAG 2.1 AA). Every story is checked by axe and fails on a violation. The
  Accessibility tab of each story lists the keyboard model and ARIA. This is not an audit: the status is *non audité*.

## Why `mk` selectors in Angular

Angular reserves unprefixed element selectors for the HTML standard, and its lint rules
(`@angular-eslint/component-selector` and `directive-selector`) require a prefix. So Angular is the one place with a prefix:
`mk-` for components (`<mk-tabs>`) and `mk` camelCase for attribute directives (`<button mkButton>`), while the three custom elements
(`workflow-loom`, `command-bar`, `plugin-slot`), the CSS classes (`.button`), React names and the HTML recipes stay
unprefixed.
